# Whole-receipt mint declaration

This initial contract supplements the existing WarehouseReceipt type without changing the submitted model or ledger. It retains the whole commodity quantity/unit, warehouse receipt and bill numbers, issuer, registrar, location, complete bill terms, applicable commodity template and version, required commodity attributes, original-document mapping, controlled-access mapping, trade/registration deadlines and the Oracle voucher format/path declared at mint.

Templates explicitly declare applicable and required fields. Missing, duplicate or inapplicable attributes are refused. The fixture template is an engineering example, not a CME commodity standard or institutional endorsement. Real asset/template schema correspondence must be verified by the existing asset implementation. One receipt maps to one whole NFT; goods quantity is preserved independently from the indivisible trade unit. The in-memory uniqueness book rejects duplicate asset, receipt or issuer/warehouse-document mappings and changes to an already-admitted declaration. Repeated identical input is idempotent.

Time uses integer Unix seconds in UTC. New trades require time strictly before the declared stop. A registration timestamp must not exceed the trade stop and must satisfy the separately declared LT/LTE registration deadline. Equality is explicit, not a hidden grace period. These helpers do not authenticate Oracle time or provide an atomic deadline/rollback transition; the canonical authority must do that at integration.

The format declaration describes the one off-chain registration voucher that the Oracle accepts and represents on chain. This module does not accept voucher originals, update holder independently, issue a second registration receipt or wait for a late receipt. Bill pickup terms are retained as document data; no EX pickup, transport, warehouse-out or burn operation is introduced.

Only opaque non-secret access mapping IDs are accepted. A metadata candidate is returned only after explicit existing-schema, controlled encrypted-storage mapping and non-secret metadata checks. Callbacks may not mutate the declaration. The contract contains no credential generation, encryption implementation, secret-store access, private-key custody or chain send. Regex validation cannot prove that an arbitrary label is non-secret; the real authenticated mapping/privacy adapter remains required. Synthetic callbacks returning true are unit fixtures, not actual encrypted-storage or privacy acceptance. Errors do not echo rejected field values.

This JSON declaration is an engineering contract, not an asserted existing NFT ABI. Real schema/serialization, controlled-store permissions and authenticated privacy evidence must be bound to existing implementations. The book is a serialized in-memory projection, not a concurrent durable mint registry. Asset validity, mint execution, Oracle integration, installed UI and deployment remain unproved.

Ten authored unittest methods cover complete goods/terms metadata, per-commodity templates, missing fields, fixed declarations, duplicate underlying mapping, exact deadline equality, invalid time types, all three declared paths, opaque mapping/storage refusal and privacy/mutation refusal. Validation command: python -m unittest integration.test_mint_specification -v. At initial submission all tests, CI, real schema/storage validation, browser, mint, deployment and chain acceptance are NOT_RUN. Existing producer/submitted implementation files remain unchanged.

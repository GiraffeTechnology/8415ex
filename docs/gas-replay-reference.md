# Isolated gas replay reference adapter

This module is an EX recovery/idempotency metadata reference only. It is not the authoritative ArtFi or Wallet task journal, SettlementCoordinator, principal account, native gas ledger or an additional settlement architecture. SQLite is expressly limited to this isolated optional reference/test adapter. It is not selected as an approved host deployment default, and importing this module creates no connection, database, table, service, credential or wallet operation. Formal storage integration must bind the existing approved project MySQL/runtime and original authoritative task/settlement interfaces; those exact bindings remain an integration dependency.

The caller supplies an exclusively owned isolated SQLite connection and explicitly initializes its fixture table. No PRAGMA or shared schema/security setting is changed. Existing active transactions are refused before any commit/rollback. BEGIN IMMEDIATE serializes a new append with replay, expected-head comparison, validation and event insertion. Event ID plus canonical command bytes provide duplicate reconciliation; the same ID with different content is refused. Original accepted results remain historical operation results, not a substituted current snapshot. recover returns current projected state separately.

Each event binds the pinned projection contract, sequence, event ID, canonical command/result and previous hash. Recovery checks the sequence/hash chain and recomputes each result. This detects accidental content/sequence corruption, not privileged tampering or unanchored tail truncation. It is not an authenticity certificate. An approved external checkpoint/native journal is required for authoritative completeness and rollback protection.

A read-only verifier explicitly distinguishes history proof checks from current authorization, balance and send-bound checks. Historical replay must authenticate the original accepted facts at their original identity/time; current send checks must still validate effective authorization and funds. The journal cannot turn synthetic evidence into verified real wallet facts. Verifiers must not sign, send, freeze, debit, release, top up or cause any other financial effect. All projection snapshots retain wallet/send NOT_RUN and receipts explicitly state no financial effects were dispatched.

Pending/unknown attempts, failed-transaction consumption, quote revisions and original operation identities are replayed without resetting totals. An acknowledgement failure after commit is UNKNOWN; query the original event ID through a clean/reopened connection before deciding anything further. This is append-outcome reconciliation, not permission to resubmit a wallet transaction. Unknown financial execution must first be reconciled by original intent/transaction/fee evidence in the original authoritative system.

This initial implementation replays the full isolated event history and is not a production-scale storage design. It uses the exact parent gas projection contracts, not an asserted deployed ABI. Original MySQL/native task journal mapping, durable authoritative atomic wallet accounting, crash/backup/restore acceptance, application mounting and real provider execution remain outstanding. Do not deploy this fixture store as a fallback because another binding is missing.

Ten authored unittest methods cover actual fixture-file reconnect, consumed/unknown state preservation, duplicate and changed event handling, stale-head/current-proof refusal, after-commit acknowledgement loss and ID lookup, hash corruption, historical-proof refusal, foreign transaction protection and quote-revision replay. Proposed validation-owner command: python -m unittest integration.test_gas_budget integration.test_gas_reconfirmation integration.test_gas_budget_journal -v. All tests and real DB/native journal/wallet/provider/UI/deployment/chain validation are NOT_RUN at initial submission; no product database is initialized by source authoring.

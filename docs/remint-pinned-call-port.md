# Original pinned remint call port

`RemintPinnedCallPort` joins the existing fixed getter encoder with an installed original read transport and exact-response verifier. It implements the `call_original_at_block` callable expected by the original history snapshot. The original header reader remains in place. The port makes one read call per requested getter, authenticates the exact returned bytes and request/block binding, checks the JSON-RPC reply and decodes its ABI result before returning the original binding/data shape.

The host installs its actual existing transport and verifier. This module does not select an RPC URL, credential, account, provider, timeout, contract code or trust policy. The transport retains those settings and must send the exact detached request without retries or route substitution. The verifier must authenticate actual provider/chain/code/ABI and observed-block response provenance. A fixture returning true or echoing a request is not independent proof.

A fresh UUID string identifies each JSON-RPC exchange. It is not a task operation ID, transaction nonce, reservation or replay token. Replies must match that ID and the 2.0 protocol version, contain one result, and contain no error. Duplicate JSON keys, batches, null results, malformed UTF-8, noninteger JSON numbers and oversized bodies are unavailable. The [JSON-RPC specification](https://www.jsonrpc.org/specification) defines request/response correlation and mutually exclusive result/error fields. This client uses the strict single-response success shape.

The fixed encoder retains its exact EIP-1898 block-hash and explicit canonical policy. No latest, safe, finalized or alternate-provider fallback exists. Empty/reverted or truncated ABI data never becomes a zero result; actual scalar zero remains a decoded observation. Declaration and link results reuse the existing decoders. A failure prevents a partial history result, without touching a checkpoint, journal, funds or UNKNOWN operation.

This stage retains the exact three getter-encoding files and ancestry from its predecessor and composes them with the current merged history snapshot source. Eight new synthetic supported-Linux definitions exercise the complete six-call history read, exact raw verification, malformed/error replies, scope isolation, ABI failures and genuine zero, single-call failures, bounds/input detachment and distinct RPC IDs. Fixture transport, cryptography and authentication are synthetic. Author execution is NOT_RUN. No endpoint has been selected or contacted; actual installed provider/ABI verification, current-source testing, runtime/browser and native financial/chain acceptance remain outstanding.

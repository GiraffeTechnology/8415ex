# Original receipt gas observation

This read-only adapter converts authenticated mined receipt facts into the existing GasConsumption contract. It uses exact gasUsed multiplied by effectiveGasPrice, never cumulativeGasUsed, the submitted gas limit or a quotation. Both status zero and status one retain their consumed gas; status one is not proof of Oracle registration, principal release or business completion.

The input is the exact UTF-8 JSON bytes of the receipt result, not the JSON-RPC envelope. The original transport must authenticate the envelope/request ID and extract the original result bytes without substituting cached data. No RPC address, provider credentials or new transport is selected here. Only explicit Sepolia context and standard transaction types zero, one and two are accepted. Blob/additional-fee models and type four require a separately reviewed original adapter rather than silently dropping fees.

The injected verifier receives the raw bytes and SHA-256 together with the original attempt, transaction, explicit chain, mined block identity, quantities and original proof reference. It must establish the actual original wallet journal attempt-to-transaction binding, approved chain, current canonical inclusion and the existing finality policy. The module cannot establish these from a receipt object alone. A synthetic true callback is not evidence of a real chain or wallet binding. A null result stays unknown and yields no consumption. Missing mined fields, invalid quantities, duplicate JSON keys, wrong transaction/chain, false or unavailable verification refuse the observation. No retry or alternate provider is invoked.

The returned observation retains the exact raw hash and block identity, and its consumption() method makes the existing GasConsumption value. The caller must pass that evidence through the original native journal/settlement coordinator and its existing deduplication and cap checks. This module does not append to a financial journal, call budget.reconcile, debit a wallet, close a budget, unfreeze, send or sign. Do not treat this as a second settlement architecture. Unknown outcomes remain reserved under the existing coordinator. A reorg before accepted finality must prevent verification; a reorg after previously accepted accounting requires the original recovery path and cannot be silently reversed or replayed here.

Protocol source: [Ethereum JSON-RPC receipt specification](https://ethereum.org/en/developers/docs/apis/json-rpc/#eth_gettransactionreceipt). The source describes per-transaction gasUsed, effectiveGasPrice and status. Type support here is intentionally narrower than future network protocol support.

Validation input: eight authored unittest methods, NOT_RUN. Proposed validation-owner command: python -m unittest integration.test_receipt_gas_observer -v. Initial source only; no product import, compiler, tests, provider query, chain confirmation, wallet accounting, deployed route or final acceptance has been executed by the author.

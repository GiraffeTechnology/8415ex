# Gas disclosure and wallet confirmation view

This initial server-rendered view consumes the exact quote contract on its parent source. It displays the fee maximum and statistical P50 in ETH/USD, quote/version, covered actions, validity, same-instant FX, sample window and raw sample identities/hashes. The form explains separate gas prepayment, failed-transaction consumption and unused-balance release. Every dynamic label, token and attribute is HTML escaped; the POST route must be supplied explicitly and remain same-origin.

The existing application must mount the controller under its authenticated route and CSRF protection. Buyer, canonical action identity, wallet grant and fee amounts come only from the trusted server session and current quote resolver. Posted buyer/fee fields, repeated/list values, edited digests, missing consent, stale versions and invalid CSRF are refused before the wallet adapter is called. A changed current quote requires redisclosure and confirmation. The wallet adapter result must bind the same buyer/action/grant and complete quote digest, with a valid proof reference and time. A changed quote during confirmation is refused. Unknown wallet result is not accepted as confirmation.

The checkbox requests the existing wallet confirmation; it does not create a second EX spending authority. The wallet adapter must authenticate and verify the actual proof, preserve existing grant constraints, and reconcile duplicate or outcome-unknown confirmation requests under the same canonical operation. This module does not sign, freeze, debit, unfreeze, register or broadcast. Neither the fixture adapter nor a typed confirmation is real wallet evidence by itself.

Integration still required: mounting into the existing authenticated application, the actual wallet confirmation adapter and proof verifier, principal plus cap-sized gas freeze gates, refresh/top-up and aggregate accounting preservation, installed browser/UI validation and real provider/chain acceptance. The current form is usable source but has not been installed or exercised here. No new route URL, provider, credential or deployment parameter is invented.

Eight authored unittest methods cover visible dual disclosure and provenance, escaping, server-bound confirmation, edited/stale forms, posted buyer/fee tampering, expired/revised quotes and mismatched/unknown wallet results. Proposed validation-owner command: python -m unittest integration.test_gas_budget integration.test_gas_confirmation_ui -v. Tests, hosted CI, browser, deployment and wallet/chain execution are all NOT_RUN at initial submission. This source builds on the exact gas-budget parent commit; its parent tests must be evaluated at this combined tree rather than inherited as passed.

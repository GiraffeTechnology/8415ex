# Gas quote, confirmation and budget evidence contract

This independent initial module keeps all fee amounts as integer wei and uses exact rational arithmetic for median calculations. Odd sample counts use the middle sorted value; even counts use the mean of the two middle values. A half-wei statistical median is retained exactly in the display; it is not rounded into a spend authorization. Cap and median each expose ETH and USD using the same quoted FX observation. Sample identity, scope, chain, observed time, block number, source and raw SHA-256 are retained for recomputation. Duplicate samples, single-point statistics, cross-scope/chain samples, future windows and mismatched FX times are refused. Sample provenance still requires the production evidence adapter to authenticate actual input records.

## Buyer and wallet binding

BuyerConfirmation binds the entire quote digest, buyer, canonical action digest, existing wallet grant and confirmation proof. The quote digest includes quote ID/version, covered actions, cap, validity, statistics and the exact USD disclosure. GasFreeze must be verified, known FROZEN, cap-sized, same buyer/chain/quote and explicitly GAS_PREPAYMENT; price principal cannot substitute for it. The callback must verify the real wallet grant and confirmation proof; a caller-supplied true value is never evidence of a real signature. No new approval authority or credential is created.

Before a send, the adapter must prove the current fee upper bound, original grant, action binding and effective freeze through the send-bound verifier. The sum of actual consumption and every outstanding attempt upper bound cannot exceed the confirmed aggregate cap. A retry or split cannot reset that cap. Quote ID changes under the same budget are refused; a different budget for the same canonical action identity is also refused. Canonical action identity must be derived and verified by the adapter, never chosen afresh to evade the budget.

## Consumption and remaining balance

Reconciliation requires a verified canonical transaction hash and exact actual gas cost. SUCCESS and FAILED both consume actual gas. Unknown outcome retains its reservation and blocks closing. The same evidence is idempotent; changed evidence, reuse of a transaction under another attempt, and cost above the proven reservation are refused without altering the prior projection. Once no attempt is pending, closing produces an unused-balance unfreeze proposal and is idempotent. This does not itself debit or unfreeze a wallet: every snapshot explicitly marks walletDebit, walletUnfreeze and transactionSend NOT_RUN.

## Integration work still required

This is a serialized in-memory projection, not a persistent financial journal or a concurrent send coordinator. It has no wallet/provider implementation, signature verifier, actual balance proof, principal escrow integration, automatic transaction dispatch or UI confirmation handler. Durable identity replay across restarts, atomic wallet settlement, zero-send cancellation evidence, refreshed quotation/top-up and reconfirmation while preserving the original aggregate operation, and the actual UI flow must be joined to existing approved interfaces before end-to-end acceptance. An expired, insufficient or exceeded budget refuses the affected send; it cannot be silently raised. This is a missing integration path, not an undecided cap policy. Shared-operation fee allocation remains outside this module.

Initial validation input: twelve authored unittest methods cover exact odd/even P50 and ETH/USD, provenance/schema refusals, confirmation binding, separate known freeze, aggregate retries, failed consumption, duplicate accounting, unknown outcome, stale/uncovered bounds and operation identity. Validation command: python -m unittest integration.test_gas_budget -v. At submission all are NOT_RUN. No hosted CI, live wallet, browser, deployment, Sepolia or archive acceptance is claimed.

# Original remint receipt observation

`RemintReceiptObserver` correlates the original remint receipt without issuing RPC or changing journals. It reuses `ReceiptGasObserver` for the exact raw receipt, original attempt/transaction association, fee arithmetic and original canonical/finality verifier. The host separately supplies its original ABI log decoder bound to the deployed contract/code. A synthetic verifier or decoded object is not real chain evidence.

For a successful receipt, each original log must retain its transaction/block binding, original ordered index and nonremoved status. Only the explicitly bound contract's events enter correlation. The selected NFT0Reminted operation must match the original operation ID, old token, actor and stable bill; its actual new token is derived from the event. Matching old-token burn, new-token mint and the complete original replacement declaration must appear in the original contract's event order. Unrelated contract events and other unrelated operations cannot substitute for those records.

The returned projection omits actor/contract addresses, private proof references, raw log bytes and errors. It preserves actual token IDs, declaration hashes/currency words, receipt identity, correlated log indices and consumed ETH gas wei. It does not rewrite the prepared new-token mapping or unchanged original declarations, registration, trade or funds history.

NOT_MINED_AT_READ, FAILED_RECEIPT and NO_MATCHING_EVENT_AT_READ remain distinct. An idempotent same-operation contract call can succeed without emitting a second remint event; no matching event does not prove operation or pending-task absence. Successful correlation alone establishes neither business settlement nor a new financial action. Receipt status does not independently establish finality. No observation grants replay, signing, broadcast, reservation release or UNKNOWN reconciliation.

This stage implements an original transaction-evidence part of EX-REMINT-02/04/05 and T-64/T-66/T-67. Eight synthetic approved-Linux test definitions cover actual new IDs, exact receipt/log scope, original event order, failed/pending/no-event distinctions, replacement declarations, verification and privacy. Author execution is NOT_RUN. No original receipt was fetched or transaction submitted by this source change. Actual deployed ABI/authenticated source, current-source validation and native-chain acceptance remain outstanding.

# Optional collateral selection on an empty catalogue

An explicitly empty read-only catalogue may opt into the existing collateral
scenario selector. The constructor option is collateral_selection=True; the
existing module CLI exposes --collateral-selection. Omitting it preserves the
previous unmounted route and market response. The original loopback listener,
declared source identity, Host guard and read-only catalogue contract remain.

The shared selector is reused rather than creating another financing engine.
The operator-selected empty-directory composition requires an original
NftDirectory with no receipt bindings and an explicit boolean option. The
existing composed-workbench path keeps its original default behavior. The market
adds the selector's six-language navigation through its existing handler hook.

BTC/ETH remain simulation labels and warehouse NFTs remain a visible category.
Without receipt bindings no warehouse NFT or target is invented. Selection
does not establish ownership, mapping or collateral eligibility. Valuation, LTV,
loan amount, interest, maturity, liquidation and returns remain undefined.
No wallet, Oracle, gas or reference component is configured by this option, and
demo, snapshot and operation routes remain unavailable. POST is refused.

Eight synthetic HTTP regression definitions cover default behavior, all six
locale links, honest crypto and absent-NFT choices, invalid fields, unchanged
health and closed command routes, write refusal, Host validation, idempotence
and explicit opt-in. They have not run. This source does not change an installed
listener or proxy, nor establish browser, real collateral or product acceptance.

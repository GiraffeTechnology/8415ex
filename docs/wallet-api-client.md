# Original Wallet API client

This EX client follows the original Wallet auth-service and login-core protocol at source f57e298b8680588cc9458c43b69eb9d58e9d5567. It calls the existing bootstrap, wallet challenge, proof, session and task endpoints. It does not discover capabilities, provision identities, widen scope or implement a second authentication scheme. The EX profile remains Sepolia 11155111; the separate Hoodi test configuration is not borrowed.

The exact login message is reconstructed and matched against the server challenge before passing it to the existing authorized login-message signer. Tenant, origin, account, chain, request, nonce and millisecond expiration remain bound. A transaction-signing method is not a substitute. Cookies and CSRF remain private in memory; the returned login/session summary excludes both. Each task call revalidates the original server session before the request. The existing server continues to validate credential revision, CSRF, grants, native child schema, reservations, nonce and execution.

Only the original task payload field sets are accepted. Server-owned test exemption decisions are not client flags. Execute errors are treated conservatively as UNKNOWN: this client never automatically repeats a send, and the same client will refuse that operation's execute path after uncertainty. The existing recover/observe/status routes remain available. A successful recovery response does not automatically clear uncertainty or authorize another send. The client is not a durable journal or an economic/finality verifier; original server persistence and reconciliation remain mandatory.

The transport uses the explicit configured origin only, certificate/hostname verification, no redirects, no ambient proxy, bounded body/timeout and JSON parsing. Cleartext is accepted only by an explicit loopback-test option. No endpoint, actor, tenant, cookie or signer default is shipped. No actual installed endpoint or login-message signer is asserted by this source stage. Thirteen synthetic loopback HTTP definitions are separate from acceptance against the exact installed original Wallet service, authoritative Oracle and native financial writer.

Calls on one client instance serialize cookie/session/task mutation. An UNKNOWN marker survives logout and relogin on that instance. This does not coordinate separate client instances, processes or restarts; the original native journal and idempotency remain mandatory. Source v4 and its three additional definitions have not been run. A detached task payload is captured before the session HTTP read; the UNKNOWN key and outgoing request use this same snapshot even if the caller mutates its original object.

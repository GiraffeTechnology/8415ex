# Original same-block remint getter call encoding

`RemintReadCallEncoder` prepares the four read-only getter calls used by the original remint history snapshot port: declarationOf, predecessorOf, successorOf and activeTokenForBill. It accepts the exact semantic binding already used by that port and produces a detached copy plus an `eth_call` method/parameter pair. The original application supplies its existing contract, installed Keccak-256 function and explicit canonical-read policy. It retains actual provider chain/contract-code authentication, request ID/envelope and transport.

Only the four fixed signatures can produce calldata. Each request contains the original destination, four-byte selector and one exact uint256 or bytes32 argument. Decimal uint256 text preserves the full range without JSON integer rounding. Zero mapping arguments remain encodable ABI values; this byte layer does not invent business eligibility. Bill labels are not hashed into identifiers. No sender, value, gas, nonce, signer or effect method is generated.

The second parameter uses the supplied observed block hash and original explicit requireCanonical policy, following [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898). The block number and timestamp remain in the private binding for response correlation, while the actual call parameter selects the hash. There is no latest, safe, finalized or block-number fallback. A canonical-read request is not proof of canonical response or finality. An unsupported original transport affects this read port; no alternate route, provider or execution gate follows.

The installed original call port must actually execute that exact read and authenticate its response before returning the existing binding/data shape. Encoding, echoed JSON and synthetic callbacks do not establish that fact. This module performs no network call, state load/save, transaction enquiry, signing, broadcast, UNKNOWN reconciliation or financial release. It is independent of the pending workbench composition and event-log decoder stages.

Eight synthetic supported-Linux definitions cover all fixed getters, full uint256 precision, exact bill words, block hash policy, input/context isolation, effect exclusion and crypto errors. Fixture selector bytes are synthetic port outputs, not actual Keccak vectors or deployed ABI evidence. Author execution is NOT_RUN. Actual installed crypto, provider/EIP-1898 support, current-source validation, runtime/browser and native-chain acceptance remain outstanding.

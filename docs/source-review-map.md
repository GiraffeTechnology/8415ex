This is navigation, not a coverage certificate. A listed file may contain a
model, adapter, declaration, observation or boundary rather than an installed
effect implementation. Its Git blob and size identify the file to inspect.
A requirement remains unaccepted until its own assertions and original runtime
evidence are established. This map executes nothing and inherits no prior pass.

## Use the map

1. Start from a requirement ID or a T-01 through T-84 case. Read the full current
   PRD assertion and all linked requirements, including negative constraints.
2. Inspect the pinned source anchors and their actual callers, trust boundaries
   and integration inputs. A matching file name, hash, type, label or status
   string does not authenticate an external observation.
3. Record applicable exact-source checks separately from actual configuration,
   deployment, browser, authority, Wallet, Oracle, funds, native journal,
   transaction receipt and finality observations.
4. Keep a missing interface or source input scoped to its dependent actions.
   Do not create extra human approval, full-readiness, cleanup or migration
   prerequisites, and do not guess original execution parameters.
5. Preserve the assertion and original evidence when inputs change. A changed
   requirement, source, configuration or operation needs the applicable fresh
   evidence; a historical pass cannot be relabelled as current acceptance.

## Evidence boundaries

- Matching is not registration or settlement. Recorded owner, effective holder,
  current admission, chain finality and signatures are different observations.
- Reference prices and simulated whole-NFT quotes/trades are different data.
  Failed or stale reference inputs remain unavailable/stale with their actual
  source precision and last-success observations.
- Principal stays in its one selected allowed currency. ETH gas, pending
  reservations, consumed fees and unused-ETH proposals are separate. A projection
  cannot prove that an actual debit, refund, release or unfreeze occurred.
- A remint declaration or planned old/new pair is not proof of atomic burn/mint
  or installed bidirectional token links. A zero operation read is not proof
  that no pending native operation exists.
- Source/HTTP identity, CI, simulation and rendering each have useful, limited
  meanings. None independently establishes native financial/chain acceptance,
  an editable presentation, a playable film or complete product delivery.
- Retired collection, late-voucher grace, second business payment, forced
  custody and reverse-hop return requirements must not be restored through
  historical source or notes. Apply the current PRD directly.

## Coverage index

The JSON retains every individual requirement, its exact baseline source
anchors and current case references. It also retains every case's full assertion
and requirement links, including cases without a single-module implementation.
Every row uses `NOT_ESTABLISHED_BY_THIS_MAP`; the overall state is `OPEN`.
Document identity and complete enumeration do not certify semantic coverage.

This documentation adds no runtime entry point, validation prerequisite,
execution gate or replacement acceptance store.

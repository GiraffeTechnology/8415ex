# Optional scenario context HTTP entry

`mount_market_scenarios` adds `/scenarios` to the original native workbench, or
to an explicitly selected empty catalogue. It reuses the original NFT directory,
Host guard, response handling and listener. The original empty catalogue CLI
accepts `--scenario-selection`; the default startup remains unchanged. This
option composes with `--collateral-selection` without duplicate navigation.

Six-language market links lead to the original scene renderer. Query input is
bounded to one locale, scene, crypto context, commodity context and original
target key; extra, duplicate and unknown fields are refused. POST never parses
a body or dispatches business work and closes the connection; the original Host
guard applies before either GET or POST handling. Other original routes retain
their behavior.

The new entry preserves empty NFT state and does not configure a business
gateway, gas controller, reference feed or registration source. It does not
change readiness or make a scene selection into a hedge, finance operation,
arbitrage opportunity or executable order. Real receipt eligibility, asset
mapping, market data and economic mechanisms remain separate acceptance work.

Eight synthetic HTTP regression definitions are authored, not run, covering
default startup, six languages and three scenes, simultaneous selector mounts,
query/Host/POST refusals, unchanged health/empty state and explicit mounting.
No service, proxy or installed source is changed by this source stage. Actual
browser interaction and native business acceptance are not established here.

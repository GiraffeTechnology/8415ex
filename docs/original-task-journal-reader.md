# Original task journal read-only consumer

This initial consumer follows the actual public createNftTaskJournal entry in ArtFi source commit 5e7cc4cd482be71431d904439ef79d1ab5d7eade, apps/web/src/lib/nft/task-journal.ts (blob b132ef9c67bee3af14541bf9b110a0985f3da4e0). That source declares artfi-task-journal/1 and a get/create/update function contract. Its server-owned HTTPS transport, installed mTLS peer, request-bound capability and same held grant gate are required inside the existing runtime. The Go composition in apps/api/internal/httpapi/nft_task_journal_composition.go (blob e1838f1ae06845742cb9b7fda5d5e2fc45027bc7) uses the existing MySQL nft_operations journal and explicit installed configuration.

The consumer accepts an adapter already bound to that original runtime entry, calls only original_journal(principal, 'get', {id: operationId}), and validates the returned unsigned operation. It adds no HTTP client, TLS/capability issuer, bearer/session bridge fallback, credential, environment default, table or database. The callback is an engineering integration seam, not proof that the actual installed runtime is available. Its synchronous Python adapter must await/resolve the real original entry in the existing approved runtime; no such bridge is installed or invoked by this source batch. Missing adapter remains UNBOUND.

Principal keys, digest/reference formats, native operation identity, unsigned-payload filtering, request hash, safe integer bounds, revision/status and plan principal/account/chain correspondence are preserved. The caller supplies exact approved chain and public wallet context; a different network or wallet is refused. Original request and task/executor digests are copied without recomputing or replacing the original plan review or authorization digest. Bounded JSON encoding and offset-bearing timestamps are required. This consumer is deliberately stricter about timestamp offsets than Date.parse and refuses unsupported encodings rather than fabricating values.

No create/update or retry occurs. An unavailable original get is reported without another network path. Nested signatures, raw signed transactions, access/capability secrets and other prohibited payload fields cannot reach the projection. Errors do not echo payload values. A native task status such as accepted or confirmed remains its original journal status, not evidence of EX Oracle registration, principal freeze/release or gas settlement; canExecute stays false and those financial/registration dimensions remain NOT_VERIFIED.

Backend alignment still requires specific semantic mapping. At the same ArtFi commit, WholeArtworkMarket.sol fillIntent performs buyer-to-seller payment transfer plus NFT transfer at fill time; its whole-artwork EIP-712 client/market is not proof of EX pre-frozen principal, Oracle-gated segment release, owner/holder separation or suffix rollback. Its source must not be silently substituted for those EX requirements. No fractional/charity asset path is introduced here. Actual native journal/SettlementCoordinator reuse, approved EX asset/action/segment mapping, installed adapter/peer/grant evidence and real UI/provider acceptance remain outstanding.

Eight authored unittest methods cover original get/digest preservation, input-scope refusal, foreign-operation/chain/wallet/principal refusal, nested-secret rejection, malformed result refusal, session/request rejection, no-retry unavailable handling and size/integer limits. Proposed validation-owner command: python -m unittest integration.test_original_task_journal_reader -v. All tests, CI, native service calls, wallet, browser, deployment and chain acceptance are NOT_RUN at initial submission. No ArtFi or already-submitted EX file is changed.

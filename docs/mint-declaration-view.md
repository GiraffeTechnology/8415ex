# Read-only mint declaration review

This server-rendered view uses the pinned mint specification contract. It displays the full declared goods quantity/unit independently from the one tradeable NFT, warehouse and bill numbers, issuer/registrar/location, per-commodity attributes and referenced template, opaque document/access mappings, both exact UTC deadline conditions and the single Oracle voucher format/path. Bill terms are retained in full as escaped text.

The view reruns the explicit existing schema, controlled encrypted mapping and non-secret metadata verifiers before rendering. Every value and label is escaped. It has no secret input, fetch link, mint form, signing button, registration endpoint, pickup or burn action. The initial account at mint is clearly identified; this view does not invent a current owner/holder observation. Time eligibility is labelled as only a declared-time condition and never represented as trading permission. Declaration candidate, unproved mint/asset validity and absent institutional endorsement remain visible.

The fixture verifier is not actual storage/schema acceptance. Existing application mounting, verified real declarations, current Oracle/owner/holder state and actual browser validation remain integration work. No deployment route, provider, secret-store setting or permission is invented. This source does not replace the existing workbench or modify submitted producer files.

Five authored unittest methods cover full field/terms visibility, escaping, privacy/mapping refusal, the same display contract for all three declared paths, and invalid observation time. Proposed validation-owner command: python -m unittest integration.test_mint_specification integration.test_mint_declaration_view -v. All tests, installed UI/browser, secret-store validation, actual mint, deployment and chain acceptance remain NOT_RUN at initial submission. Parent test results must be evaluated at the combined tree rather than inherited as green.

# Two-category collateral scenario selection

The scenario selector accepts either BTC/ETH crypto-asset labels or a whole
commodity receipt NFT already present in the original workbench directory. A
target receipt may be selected from that same directory. Public opaque NFT keys
and numbered labels are used; private receipt, wallet and account identifiers
are not rendered. No selected category or asset is inferred on the initial page.

`mount_collateral_selection` adds `/collateral` to the original composed server
and retains its existing handler for other routes. The six-language form uses
GET and holds no funds or persistent selection. POST is refused. This page is a
DEMO scenario choice, not an asset ownership or collateral-eligibility proof.
BTC is a scenario label, not a new network, wrapped asset or bridge integration.

Mechanism parameters remain absent. The selector computes no LTV, valuation,
borrow amount, interest, margin, liquidation, maturity or return. It dispatches
no wallet action and changes no original spot-order eligibility, NFT0 payment
currency rules, ETH gas rules, matching priority or registration settlement.
Missing NFT data stays unavailable for NFT selection while the independently
defined scenario categories remain visible.

Seven synthetic regression definitions cover both categories, six-language
routes, absent receipts, invalid or finance-bearing parameters, identity
exclusion, idempotent navigation mounting and write refusal. They have not been
run. This source does not establish an installed route, browser acceptance,
real collateral execution or complete product acceptance.

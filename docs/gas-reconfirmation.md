# Confirmed gas budget revisions

This extension adds the missing refreshed quote and confirmation transition on the pinned gas-budget contract. It preserves the original budget ID, canonical action identity, buyer, wallet grant, chain and covered actions. The new quote must have a higher version, current validity and a fresh buyer confirmation bound to its complete digest. Broader grant, new quote ID or a refreshed clock cannot erase prior spend.

A revision is refused while any attempt remains unresolved or after the budget is closed. GasAdjustment records authenticated wallet evidence of the previous quote/freeze, new quote/freeze, cumulative actual consumption and effective remaining gas prepayment. Its account kind must stay GAS_PREPAYMENT and its status must be APPLIED. The effective frozen balance must equal the new confirmed cap minus all actual consumption already recorded, including failed-transaction gas. Insufficient, failed or outcome-unknown top-up evidence leaves the prior projection unchanged. The verifier must authenticate the real wallet facts and original authorization; this module never performs the top-up or release itself.

After a verified revision, the original consumption, transaction deduplication and canonical-operation mapping remain in place. Existing reservation logic applies the new cap to actual spend plus outstanding upper bounds. A repeated identical revision returns current state without resetting subsequent reservations or spend. Further transactions consume only their own actual fee; final unused balance is derived from the revised total cap minus accumulated actual costs.

This is an initial serialized in-memory extension, not a durable journal or actual wallet implementation. It deliberately uses the parent projection internals and must be reviewed with that exact parent when integrating or revising the base. Adapter ABI mapping, authenticated wallet readback, atomic durable debit/top-up/unfreeze, installed UI and live execution remain outstanding. Do not infer a real APPLIED wallet change from synthetic typed fixtures or from this source.

Eight authored unittest methods cover cap increase without failed-fee reset, duplicate revision, unresolved-attempt refusal, insufficient/unknown/wrong-account adjustment, stale or widened confirmation, wrong operation/previous freeze, subsequent actual consumption and verifier refusal. Validation command: python -m unittest integration.test_gas_budget integration.test_gas_reconfirmation -v. At initial submission all tests, CI, installed UI, provider, deployment, wallet writes and chain acceptance are NOT_RUN. Existing submitted source files are unchanged.

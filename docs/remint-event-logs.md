# Original remint event log decoding

`RemintEventLogDecoder` is the callable ABI decoder for the existing `RemintReceiptObserver`. It decodes the original contract's Transfer, NFT0Declared and NFT0Reminted event layouts directly from exact log topics/data. It accepts one original contract and an already-installed Keccak-256 function. Only the three fixed Solidity signatures are hashed; the standard Transfer topic is checked against its fixed vector, all topics must be distinct nonzero 32-byte outputs, and SHA3-256 is not a substitute. This vector check alone does not authenticate a cryptographic implementation or deployed ABI.

The trusted application must retain its actual original contract-code/ABI provenance and receipt verifier. This decoder neither selects nor contacts a provider. Its context must match the original Sepolia chain, contract, transaction, block, index and nonremoved log. No caller-controlled ABI or event-name selector is accepted. Unknown topics return no recognized event; malformed recognized topics/data are unavailable rather than a fabricated successful observation.

Transfer uses three indexed fields and empty data. NFT0Reminted uses three indexed fields and exactly two data words, including a canonically padded nonzero holder address. NFT0Declared uses indexed token/bill and the exact terms/currency-head/array offset of 96 bytes in its non-indexed event data. Complete ordered nonzero distinct currency words are revalidated through the existing declaration decoder. No trailing data, truncation, alternate offsets or empty/duplicate declarations are accepted.

The existing receipt observer still verifies the original raw receipt first, requires burn/mint/declaration/remint order and derives the actual replacement token. Neither decoding nor event correlation establishes business settlement, finality, UNKNOWN absence, replay permission or funds release. Addresses remain private decoder inputs/results used by the correlator; its public projection remains identity-free.

Eight new synthetic supported-Linux definitions cover fixed signatures, SHA3 rejection, transfer and declaration layouts, exact dynamic tails, remint padding, context conflicts, unknown/known topic behavior and an ABI-shaped four-log receipt through the original correlator. Custom-event topic values in those fixtures are synthetic Keccak-port results, not claimed actual topic hashes or deployed evidence. Author execution is NOT_RUN. Actual installed Keccak/ABI authentication, current-source tests, runtime and chain acceptance remain outstanding.

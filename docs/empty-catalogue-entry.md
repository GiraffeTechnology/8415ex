# Explicit empty catalogue entry

The read-only empty catalogue can start without a receipt binding. It renders
the existing market in six languages, with an explicit read-only label and no
fabricated NFTs, prices, gaps, owners or orders. The ordinary receipt workbench
and simulation entry retain their existing behavior.

The separate module is `exchange.catalogue_serve`. It requires the explicit
`--empty-catalogue` flag and operator-supplied `--port`, `--commit` and `--tree`
arguments. It binds only to loopback. No deployment target, proxy, service,
provider or credentials are selected or installed by this module. Source values
are declarations, not a verification of the running artifact.

The root and receipt links preserve a validated locale and lead to the empty
market. The market, catalogue, reference observation, NFT list, existing static
assets and bounded health observation are reachable. Missing receipt, demo and
execution views return unavailable. All POST requests are refused without
parsing or dispatching their bodies. There is no domain runtime, command gateway,
scenario invocation, wallet call or transaction action in this entry.

The constructor can receive an already configured original reference feed under
its existing verified policy. The CLI does not configure a feed. Missing reference
input stays not connected; the server does not invent an endpoint or a price.
Adding real receipt bindings requires the original workbench and its existing
source and execution contracts, rather than populating this empty mode.

Six remote-Linux test methods are authored for explicit empty policy, localization,
readback, unreachable simulation and writes, malformed requests and navigation.
They have not been run. This source change alone is not QA, CI, deployment,
financial, chain or complete product acceptance.
